---
name: Friction question card curl/tear mockup parity
description: Non-obvious constraints when porting the QuestionCardSwipePreview mockup (React DOM) to QuestionCardCurl (RN) — why tear uses RAF+state instead of Reanimated shared values.
---

The tear (empty-card fly-away) animation must use a **single RAF-driven `rawProgress` state** (like the existing curl animation), not independent Reanimated shared values with `withTiming`.

**Why:** the mockup derives every tear transform (translateX/Y, rotate, scale, opacity) from one `easeOutCubic(rawProgress)` value sampled on the same clock, and stops driving `rawProgress` once it crosses `TEAR_FADE_DONE` (0.4) — at that instant transform and opacity are mathematically locked together. Driving each with a separate `withTiming(...)` call (different durations/easings) decouples them: opacity reaches 0 on its own schedule while position/rotation/scale are still mid-flight on theirs, producing a visibly different (and per-frame non-reproducible) animation from the mockup. RN state-driven re-render at 60fps (already used for curl geometry) reproduces the mockup's math exactly.

**How to apply:** when porting any further mockup animation into this component (or others using the mockup/RN-port pattern), check whether the mockup drives multiple visual properties off one shared progress variable — if so, port with one RAF/state loop, not multiple Reanimated `withTiming`/`withSpring` calls.

Also: mockup drag-follow multipliers are asymmetric and must be copied literally, not approximated — up-drag 0.10, down-drag-with-back-available 0.12, down-drag-no-back `min(dy*0.22, (cardHeight+60)*0.28)`. Using a single "close enough" constant for all three visibly diverges from the mockup's feel.

`react-native-svg`'s `ForeignObject` is unreliable on native (Android/iOS) for rendering text inside curl/tear card layers — text can vanish or lag on re-render. Fix: render text with plain RN `View`/`Text` outside the SVG for unclipped layers, and use `@react-native-masked-view/masked-view` + an SVG `Polygon` as the mask for layers that need diagonal/torn clipping. Pure-SVG (no text) layers like flap reflection/crease shadow can stay as-is.

When embedding a full-screen "note/question card" overlay inside a reading pager (read.tsx), render it as a sibling INSIDE the same absolutely-positioned "scale-transform wrapper" View that sizes/positions the real page slots (same `containerWidth`/`containerHeight`), not as an independent top-level overlay computing its own size from `useWindowDimensions()`. This makes the overlay's frame pixel-identical to a real page for free, and lets it own its own `GestureDetector` without conflicting with the pager's `combinedGesture` (they were siblings already, not nested, so no gesture-composition risk). A component-internal mount-triggered `withTiming` translateX (from `containerWidth` → 0) gives a page-turn-like slide-in without needing to touch the pager's own shared-value/gesture/session-state machinery.

The reading flow's virtual page sequence is conceptually `[last article page] → [question card] → [reading complete screen]`, left-to-right. Swipe-direction convention across ALL three must stay consistent with normal page-turn physics: finger swipe right-to-left (dx negative) = move forward/right in the sequence (advance), finger swipe left-to-right (dx positive) = move backward/left (retreat) — matching how the pager's own combinedGesture treats dx<0 as "next" and dx>0 as "prev" elsewhere in read.tsx. When wiring a new step onto this chain (e.g. a gesture on the completion screen to go back to the card), copy this sign convention rather than reasoning about it fresh, and remember retreating from the completion-card step back to "last article page" must actively call the reading-session's `prevPage()` (not just hide the overlay) — the pager parks the outgoing page off-screen via a `useLayoutEffect` keyed on `currentPage`, so without `prevPage()` the last page never becomes visible again after the overlay is dismissed.

To make a 3-step handoff chain (page ↔ card ↔ complete-screen) feel like one continuous slide instead of a pop/cut, fire the state transition (mount next step / call prevPage) at the START of the outgoing element's exit `withTiming`, not on completion — and give the newly-mounted incoming element its own mount-triggered entrance animation from the same offset with the same duration/easing as the outgoing exit. Unmounting the outgoing element must wait for a separate "exit complete" callback so it stays visible (sliding off) for the full duration rather than vanishing early. A full-bleed rounded-card visual sitting inside a sharp-cornered page-slot box will show a colored margin behind it unless the card's fill ratio is set to exactly 1 (matching the slot's background/box, not a close-to-1 "safe" value).
