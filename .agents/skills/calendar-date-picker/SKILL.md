# 캘린더 / 날짜 선택 UI 가이드

## 재발했던 버그: 깨진(garbled) 달력 그리드

`artifacts/friction/app/of-space-start.tsx`의 공간 시작 마법사에서 "시작 예정일" 달력이
빈 셀 + 이상한 세로선 아티팩트로 깨져 보이는 버그가 여러 번 패치되고도 계속 재발했다.

**근본 원인은 두 가지가 겹친 것이었다:**

1. **동일한 캘린더 그리드 구현이 화면 안에 3벌 복붙되어 있었다** (시작 예정일 피커,
   발송 예정일 피커, 일정 확인 리뷰 캘린더). 각각 자체 `buildMonthGrid` 호출, 월 이동
   상태, 요일 헤더, 셀 렌더링 로직을 따로 갖고 있어서, 한 곳에서 버그를 고쳐도 나머지
   두 곳은 그대로 남아 같은 클래스의 버그가 계속 다시 나타났다.
2. **매달 최대 ~42개의 날짜 셀 전부를 `ScalePressable`(Reanimated `useSharedValue` +
   `useAnimatedStyle`을 셀마다 개별로 갖는 컴포넌트)로 렌더링**하고 있었다. 스텝이
   마운트되는 순간 수십 개의 독립된 Reanimated 워클릿이 동시에 초기화되면서 첫 페인트가
   깨지는 현상(빈 셀, 잔상 같은 세로선)이 나타났다. 개수가 적은 요소(버튼 2~3개)에서는
   문제가 없었지만, 그리드처럼 많은 개수를 한 번에 마운트하는 곳에서 증상이 드러났다.

## 필수 패턴

### 1. 셀 렌더링에 per-cell Reanimated shared value를 쓰지 않는다

캘린더처럼 수십 개의 인터랙티브 셀을 한 화면에 동시에 마운트하는 UI에는
`ScalePressable`(또는 셀마다 `useSharedValue`/`useAnimatedStyle`을 만드는 어떤
컴포넌트도) 사용하지 않는다. 대신 RN 기본 `Pressable`의
`style={({pressed}) => ...}` 콜백으로 눌림 피드백을 준다 — 셀 개수와 무관하게 워커
스레드 초기화 비용이 없어 안전하다.

버튼 1~2개 정도(월 이동 화살표, 저장 버튼 등)처럼 개수가 적은 곳은 `ScalePressable`을
계속 써도 무방하다. 문제는 "많은 개수를 동시에 마운트"하는 패턴 자체다.

### 2. 캘린더 그리드는 하나의 공용 컴포넌트를 통해서만 렌더링한다

`artifacts/friction/components/shared/CalendarGrid.tsx`에 다음이 있다:

- `buildMonthGrid(year, month)` — 월 그리드 셀 배열 생성 (SSOT, 복붙 금지)
- `CalendarGrid` — 월 이동 헤더 + 요일 헤더 + 날짜 그리드를 렌더링하는 프레젠테이션
  컴포넌트. `onSelectDate`를 넘기면 선택 가능한 피커가 되고, 생략하면 읽기 전용
  리뷰 캘린더가 된다. 셀 내용은 `renderCellContent`로, 셀 강조 스타일은
  `cellContainerStyle`로 완전히 커스터마이즈 가능하다.
- `CollapsibleDatePicker` — "선택된 날짜를 텍스트/버튼으로만 보여주다가, 탭하면
  달력이 펼쳐지는" 필드 하나를 통째로 제공하는 컴포넌트. 새 날짜 선택 필드를 만들
  때는 이것부터 써본다.

새로운 화면/기능에서 날짜를 고르거나 월별 일정을 보여줘야 한다면, 그리드를 새로
작성하지 말고 이 컴포넌트들을 가져다 쓴다. 공용 구현에 버그를 고치면 그것을 쓰는
모든 화면에 자동으로 적용된다 — 이것이 3벌 복붙 문제의 재발을 막는 핵심이다.

### 3. 날짜 선택 필드는 기본적으로 접혀 있어야 한다

달력은 화면이 마운트되자마자 항상 펼쳐진 상태로 두지 않는다. `CollapsibleDatePicker`
패턴처럼 "현재 선택된 날짜 텍스트 + 화살표 아이콘" 버튼을 기본으로 보여주고, 탭했을
때만 그리드를 마운트한다. 이렇게 하면:
- 화면 첫 진입 시 무거운 애니메이션 요소가 즉시 마운트되지 않는다.
- 사용자가 실제로 날짜를 바꾸려 할 때만 그리드가 나타나므로 UX도 더 명확하다.

## 아직 마이그레이션되지 않은 화면 (참고용, 이 스킬 작성 시점 기준)

`artifacts/friction/app/of-space-rounds.tsx`에도 자체 캘린더/날짜 버튼 구현이 남아
있다. 이 화면을 건드리게 되면 위 공용 컴포넌트로 옮기는 것을 고려한다 (별도 작업으로
분리해도 됨 — 이 스킬이 존재하는 것 자체가 "새로 만들 때 복붙하지 말라"는 신호다).
