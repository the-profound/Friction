# Friction 민지 테스트 로그인

## 사용 시점

- Friction 웹 미리보기에서 로그인이 필요한 기능을 E2E로 검증할 때
- 민지 계정의 개발 데이터로 기록함·단상·질문 대기열을 확인할 때

## 로그인 절차

1. Friction Expo 워크플로가 실행 중인지 확인한다.
2. 브라우저에서 `/login`으로 이동한다.
3. 화면 하단 개발 계정 버튼 줄의 **민지** 버튼을 누른다.
4. 인증된 탭 화면으로 전환될 때까지 기다린다. 실패하면 로그인 화면으로 돌아가 버튼을 한 번만 다시 누른다.

## 테스트 데이터 원칙

- 개발 DB는 공유 환경이다. 기존 데이터 개수나 빈 상태를 전제하지 않는다.
- 검증에 새 데이터가 필요하면 화면에서 고유한 테스트 문구를 생성해 사용한다.
- 외부 발송, 삭제, 운영 설정 변경처럼 되돌리기 어려운 동작은 하지 않는다.
- 질문 대기열을 확인할 때는 현재 질문을 기록하고, 새로고침·탭처럼 수명주기를 바꾸는 동작 전에 테스트 목적을 명확히 적는다.

## 질문 대기열 확인

기록함의 단상 탭에서 다음을 확인한다.

1. 현재 질문이 있다면 첫 카드로 보이며, `# Q.` 형식의 질문 내용이 표시된다.
2. 아래로 당겨 새로고침하면 현재 질문이 다음 질문으로 바뀌거나, 생성 가능한 출처가 없으면 안전하게 그대로 남는다.
3. 질문 카드를 누르면 편집 상태가 열리고, 같은 레코드가 일반 단상으로 승격된다.
4. 이어서 단상 화면으로 돌아왔을 때 승격된 질문이 다시 대기열 질문으로 보이지 않는다.

## 테스트 보고

- 실제로 실행한 동작, 생성한 테스트 데이터의 식별 가능한 문구, 관찰한 결과를 기록한다.
- 브라우저 콘솔과 API 로그에 오류가 있었는지 함께 확인한다.
