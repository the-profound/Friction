# 공간 기능 수정 보완 — 2026-07-27 변경 사항

## 작업 개요

4개의 변경 사항을 개발한다. Task A→B→C는 순차적으로 진행하고, Task D는 Task A-B-C와 병렬로 진행한다. 모든 작업이 완료되면 통합 단계에서 연결점을 확인한다.

## 의존 관계

Task A (운영자 참여 여부 결정 시점 변경)

└→ Task B (공간 시작 화면 단계별 분할)

└→ Task C (운영 설정 확정 단계 정보 개선)

Task D (여는 편지 예약 로직 개선)  ← 병렬 수행

통합: Task B + Task D 완료 후 연결점 확인


- Task A를 먼저 완료해야 Task B에서 공간 시작 화면의 단계 구성을 확정할 수 있다 (운영자 참여 여부 결정 단계가 제거되기 때문).
- Task B를 왼료해야 Task C에서 단계별 구조 안에 들어갈 운영 설정 확정 단계의 정보를 개선할 수 있다.
- Task D는 글 선택 컴포넌트 분리와 예약 로직 수정이므로 Task A-B-C와 독립적으로 병렬 진행한다. 다만 1회차 여는 편지 작성하기 버튼과 공간 시작 화면의 연결은 통합 단계에서 처리한다.

---

## Task A: 운영자 참여 여부 결정 시점 변경 (시작 시 → 생성 시)

### 배경

운영자 참여 여부에 따라 모집할 때 참여 인원 수 계산이 달라진다. 공간을 생성할 때부터 운영자도 참여자로 넣을지 배제할지 정해야 하므로, 결정 시점을 공간 생성 시로 옮긴다. 공간 시작 시에는 확인만 가능하도록 한다.

### 변경 내용

#### 공간 생성 화면

운영 설정 단계에 "운영자 참여 여부" 입력 항목을 추가한다.

- 질문: "운영자도 회차에 직접 참여하시겠어요?"
- 설명: 운영자가 중심글 순번에 참여하면 모집 인원에서 운영자 1명을 차감한다. 예를 들어 모집 인원 5명, 운영자 참여 시 실제 모집 인원은 4명이다.
- 입력 방식: 예 / 아니오 선택
- 단계 순서: 시작 예정일 → 예정 회차 수 → 모집 인원 → 운영자 참여 여부

공통 설정 항목의 "회차 구성 (공간 시작 시 확정)"에서 "운영자 참여 여부"를 제거하고, 운영 설정에 편입시킨다.

#### 공간 시작 화면

- 본문 구조에서 "운영자 참여 여부 결정" 단계를 제거한다.
- 운영 설정 확정 단계에 운영자 참여 여부를 확인용 정보로 표시한다. 수정은 불가하다.
- 중심글 작성 순서 배정 시 운영자 참여 여부는 생성 시 확정된 값을 그대로 적용한다.

#### 모집 인원 계산 로직

- 운영자 참여 "예": 실제 모집 인원 = 설정 모집 인원 − 1 (운영자 1명 제외)
- 운영자 참여 "아니오": 실제 모집 인원 = 설정 모집 인원 그대로
- 공간 목록, 공간 상세, 공간 참여 화면의 참여자 수 표시에 이 계산을 반영한다.
- 모집 인원 입력 단계의 설명에 운영자 참여 여부에 따른 차감 안내를 추가한다.

## Task B: 공간 시작 화면 단계별 분할 (Task A 완료 후)

### 배경

현재 공간 시작 화면은 한 화면에 모든 항목이 나열되어 있다. 공간 생성 화면과 마찬가지로 단계별로 화면을 분할하여, 사용자가 하나씩 정하고 넘어갈 수 있도록 개선한다.

### 참고: 공간 생성 화면의 단계 구조 (그대로 참고할 것)

- 한 화면에 하나의 입력 질문만 보여준다.
- 질문 문구는 사용자가 해야 할 행동이 바로 보이도록 쓴다.
- 입력값에 필요한 설명은 질문 아래에 짧게 붙인다.
- 뒤로가기를 누르면 이전 입력 항목으로 돌아간다.
- 단계의 마지막 항목을 입력하면 다음 단계로 넘어간다.
- 상단바: 좌측 뒤로가기, 중앙 "공간 시작하기", 보조 정보로 현재 단계 표시
- 하단: "다음" 버튼 (마지막 확인 단계에서는 "공간 시작하기"로 변경)
- 현재 항목을 입력하지 않으면 다음 버튼을 비활성화한다.
- 선택형 항목은 선택 즉시 다음으로 넘어갈 수 있다.

### 변경 내용

#### 단계 구성 (Task A 적용 후, 운영자 참여 여부 결정 단계 제거)

1. 운영 설정 확정
2. 회차 구성
3. 중심글 작성 순서 배정
4. 1회차 여는 편지 준비 상태
5. 시작 확인

#### 각 단계 상세

**1. 운영 설정 확정**

- 회차 수, 진행 방식(N일 간격 / 요일 지정), 중심글 개수를 확정한다.
- 공간 생성 시 입력한 예정값을 기본값으로 불러와 수정할 수 있다.
- 진행 방식: N일 간격 선택 시 중심글 간격 설정, 요일 지정 선택 시 운영 요일 다중 선택.
- 운영자 참여 여부는 생성 시 확정된 값을 확인용으로 표시한다. (수정 불가)
- (Task C에서 이 단계의 표시 정보를 추가 개선한다.)

**2. 회차 구성**

- 회차별 제목, 회차별 짧은 설명을 입력한다.
- 회차 수만큼 입력 항목을 순회한다.

**3. 중심글 작성 순서 배정**

- 확정 참여자를 기준으로 순서를 배정한다.
- 운영자가 참여하기로 한 경우 운영자도 순번에 포함한다. (Task A에서 확정된 값)
- 먼저 들어온 순서대로 순번을 보여주고, 순번이 괜찮으면 다음 달력 뷰로 넘어가서 누가 언제 글을 올려야 하는지 보여준다. 회차 기간도 함께 표시한다.

**4. 1회차 여는 편지 준비 상태**

- 1회차 여는 편지 작성 여부를 보여준다.
- 작성하지 않은 경우 [여는 편지 작성하기] 버튼을 노출한다. (통합 단계에서 Task D의 컴포넌트와 연결)
- 작성 완료 시 작성된 편지 정보를 요약해 보여준다.

**5. 시작 확인**

- 입력한 설정을 요약해 보여준다. 각 항목은 수정할 수 있다.
- 시작과 동시에 모집이 마감된다는 안내, 승인 대기 중인 코드 신청자는 자동 거절 처리된다는 안내, 시작 후 핵심 규칙 수정 불가 안내를 표시한다.
- "공간 시작하기" 버튼을 노출한다.

#### 시작 버튼 활성화 조건 (기존 유지)

1. 1회차 여는 편지가 작성되어 있을 것
2. 확정 참여자가 최소 1명 이상일 것
3. 참여자가 모집 인원 미달인 경우 확인창 승인

#### 시작 처리 로직 (기존 유지)

- 공간 시작하기 → 진행 중 전환, 모집 자동 마감, 승인 대기 중인 코드 신청자 자동 거절, 공간 상세 화면으로 이동
- 회차 틀 생성: 시작 시 확정한 회차 수와 중심글 규칙을 바탕으로 전체 회차 틀 생성

## Task C: 운영 설정 확정 단계 정보 개선 (Task B 완료 후)

### 배경

공간 시작 화면의 운영 설정 확정 단계에 정보를 추가하여, 운영자가 시작 전에 현재 상태와 예정 일정을 한눈에 파악할 수 있도록 개선한다. Task B에서 구성한 단계별 구조 안에서 동작한다.

### 변경 내용

#### 1. 참여 인원 수 표시

- 확정 인원 / 모집 인원을 표시한다.
- 운영자 참여 여부에 따른 실제 모집 인원을 함께 표시한다. (Task A의 계산 로직 적용)
- 예: "확정 3명 / 모집 인원 5명 (운영자 참여로 실제 모집 4명)"

#### 2. 공간 시작 날짜 설정 추가

- 공간 생성 시 입력한 시작 예정일을 기본값으로 불러온다.
- 운영자가 시작 날짜를 수정할 수 있도록 날짜 선택기를 제공한다.
- 시작 예정일이 이미 지난 경우, 날짜 선택기에 빨간 테두리로 표시한다.

#### 3. 종료 예정 날짜 표시

- 확정한 회차 수, 진행 방식, 중심글 개수, 시작 날짜를 바탕으로 종료 예정 날짜를 계산해 표시한다.
- 운영 설정 값이 변경될 때마다 종료 예정 날짜를 실시간으로 갱신한다.
- N일 간격 방식: 마지막 회차의 마지막 중심글 예정 날짜 = 시작 날짜 + (회차 수 − 1) × 중심글 간격 × 중심글 개수
- 요일 지정 방식: 선택된 요일 기준으로 마지막 중심글 예정 날짜 계산

## Task D: 여는 편지 예약 로직 개선 (Task A-B-C와 병렬 수행)

### 배경

현재 여는 편지 예약 기능에 여러 문제가 있다. 글 선택 화면을 공통 컴포넌트로 분리하고, 예약 로직의 버그를 수정하며, 시간 설정을 제한한다.

### 현재 문제

1. [여는 편지 작성하기] 버튼을 누르면 [글 예약 발송] 화면으로 들어가짐. 이것부터가 오류이자 문제.
2. [글 예약 발송] 화면에서 글을 추가해서 예약해도 글 등록이 안 됨.
3. 예약 시 시간을 자유롭게 설정할 수 있음. 무조건 06시로 고정해야 함.
4. 여는 편지 준비 UI에 박스가 너무 많음. "아직 작성하지 않았어요"가 들어간 큰 박스 제거 필요.

### 변경 내용

#### 1. 글 선택 컴포넌트 분리

- <보내기(OUT)>에서 글을 선택하는 화면을 하나의 독립 컴포넌트로 분리한다.
- 해당 컴포넌트를 여는 편지 예약에도 재사용하여 UI/UX를 통일한다.
- 컴포넌트 인터페이스:
  - 입력: 선택 가능한 글 목록, 예약 모드(일반 발송 / 여는 편지)
  - 출력: 선택된 글, 예약 날짜
  - 예약 모드에 따라 안내 문구와 행동 버튼 문구를 다르게 표시한다.

#### 2. 여는 편지 작성 플로우 수정

- 1회차 [여는 편지 작성하기] 버튼을 누르면, [글 예약 발송] 화면이 아니라 분리한 글 선택 컴포넌트로 바로 연결되도록 수정한다.
- 컴포넌트 내에서 글을 선택하고 예약 날짜를 지정할 수 있도록 한다.
- 예약 완료 시 글이 정상적으로 등록되도록 버그를 수정한다.
- 등록 완료 후 여는 편지 준비 상태가 "작성 완료"로 전환되는지 확인한다.

#### 3. 예약 시간 고정

- 예약 시간은 무조건 06시로 고정한다.
- 사용자는 날짜만 선택할 수 있도록 수정한다. 시간 선택 UI를 제거한다.
- 오늘을 포함한 지난 날짜는 선택 불가. 단, 현재 시각이 06시 이전이면 오늘도 선택 가능하다.
- 선택 가능한 날짜 범위: 내일부터 (06시 이전이면 오늘부터)

#### 4. 여는 편지 준비 UI 정리

- "아직 작성하지 않았어요"가 들어간 큰 박스를 제거한다.
- 불필요한 박스를 줄이고 간결한 UI로 재구성한다.
- 작성 전: [여는 편지 작성하기] 버튼만 간결하게 노출
- 작성 후: 예약된 날짜와 글 요약을 한 줄로 표시, [수정] 버튼 제공

## 통합 단계 (Task B + Task D 완료 후)

### 연결점 확인

1. 공간 시작 화면의 1회차 여는 편지 준비 상태 단계에서 [여는 편지 작성하기] 버튼이 Task D에서 분리한 글 선택 컴포넌트로 정상 연결되는지 확인한다.
2. 운영자 참여 여부(Task A)가 운영 설정 확정 단계(Task C)에 확인용으로 올바르게 표시되는지 확인한다.
3. 모집 인원 계산(Task A)이 공간 목록, 공간 상세, 공간 참여 화면에 일관되게 반영되는지 확인한다.
4. 운영 설정 확정 단계(Task C)에서 시작 날짜 변경 시 종료 예정 날짜가 정상 갱신되는지 확인한다.
5. 여는 편지 예약(Task D) 완료 후 공간 시작 화면의 여는 편지 준비 상태가 "작성 완료"로 전환되고, 시작 버튼 활성화 조건이 정상 동작하는지 확인한다.
