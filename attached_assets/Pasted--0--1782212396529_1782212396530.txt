[수정 과제]

Step 1 — 네이티브 이미지 CSS (editorHtml.ts)
 .tiptap-inline-image 규칙을 아래로 교체:
   display: block;        /* 명시 유지 */
   margin: 12px 0;        /* 1em auto(가운데) → 좌측 정렬 */
   width: auto;
   max-width: 60%;        /* 100% → 60% */
   max-height: 280px;     /* 신규 추가(세로 긴 사진 방어) */
   height: auto;
   border-radius: 8px;    /* 선택 */
 - 원본 종횡비 유지(크롭 금지), 상한 박스만 적용.

Step 2 — 웹 에디터에 inlineImage 확장 + CSS (WebViewMarkdownEditorWeb.tsx)
 - extensions 배열에 inlineImage 커스텀 노드 추가.
 - insertImage 스텁(175-177)을 실제 삽입 동작으로 구현(커서 위치 인라인 삽입).
 - proseMirrorCss(266-306)에 Step 1과 "동일한" .tiptap-inline-image 규칙 추가(display: block 포함).

Step 3 — 초기 콘텐츠 주입을 freshness와 분리 (on-01a.tsx, on-01b.tsx) ★ 두 화면 모두
 - 핵심: isDataFresh 여부와 무관하게, 콘텐츠가 도착하면 에디터가 (재)초기화/주입되도록 고친다. 스피너만으로 빈 화면을 가리는 임시방편이 아니라, 도착한 텍스트가 실제로 setMarkdown으로 주입되는 것을 보장하라.
 - on-01a.tsx:585와 on-01b.tsx:1234 "둘 다" 동일하게 처리한다(한쪽만 고치지 말 것).
 - 보조적으로, refetch 대기 중에는 에디터 영역에 로딩 표시를 띄워 빈 화면 노출을 막되, refetch 완료 후 주입이 끝나면 해제한다. (로딩 표시는 보조 장치이지 근본 해결책이 아님)

Step 4 — 웹 이미지 파싱 검증 (WebViewMarkdownEditorWeb.tsx:16-30)

 - parseHTML 규칙이 웹 에디터에서도 동작하도록 검증·보완.
