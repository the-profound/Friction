[역할] 직전 Step 3에서 isDataFresh 게이트를 두 파일에서 제거했다. 빈 화면은 해결되지만 "뒤늦게 도착한 refetch가 작성 중인 텍스트를 덮어쓰는" 회귀 위험이 생겼다. 아래 가드를 추가하고, 정합성 가드도 함께 확인하라. 수정 후 검증 결과를 보고하라.

[배경 — 기획 기준]
- 글 플로우: 작성(on-01a) → 검토/분할(on-01b, 내부 enum은 DIVIDING 유지·라벨만 '검토') → 마감(on-01c).
- 작성 단계 사진: 본문 흐름 안 "인라인 미리보기"(display:block, 60%/280px). 단, TipTap 스키마상 이미지 노드는 블록 레벨 노드여야 한다(인라인 노드 금지) — 검토 단계 자동분할이 HR을 형제로 삽입/문단 split 하기 때문.
- 자동 저장(debounce)은 기존 로직 유지.

────────────────────────
[가드 1 — refetch가 편집을 덮어쓰지 않게 (on-01a.tsx, on-01b.tsx 둘 다)]
게이트를 제거한 대신, "주입은 하되 덮어쓰지 않는" 가드를 넣어라.
 (1) 초기 1회만 주입: 콘텐츠가 처음 도착했을 때(=에디터가 아직 비어 있고 최초 populate 전)에만 setMarkdown으로 주입한다. 한 번 채워진 뒤 도착하는 refetch 응답으로는 setMarkdown을 재호출하지 않는다.
 (2) dirty 가드: 사용자가 편집을 시작한 뒤(dirty=true)에는 어떤 경우에도 refetch 결과로 본문을 덮어쓰지 않는다. (입력 중 stale→refetch 늦게 도착 시 클로버 방지)
 (3) 빈 화면 방지용 로딩 표시는 보조로만 유지하되, 콘텐츠 도착·주입 완료 시 즉시 해제. 로딩 표시가 (1)(2)를 대체하지 않는다.
 (4) 자동 저장 충돌 금지: 위 주입/가드가 debounce 자동저장을 잘못 트리거해 stale 콘텐츠를 저장하는 일이 없어야 한다. 초기 주입은 "사용자 편집"으로 간주해 저장을 트리거하지 않는다.
 (5) on-01a.tsx(handleEditorReady / 초기화 effect)와 on-01b.tsx(초기화 effect) 양쪽에 동일하게 적용한다. 한쪽만 고치지 말 것.

[가드 2 — 이미지 노드 블록 레벨 정합성 (WebViewMarkdownEditorWeb.tsx, editorHtml.ts)]
 - Step 2에서 추가하는 이미지 노드(현재 명칭 inlineImage)는 TipTap/ProseMirror 스키마상 "블록 레벨 노드"로 정의한다. PM 인라인 노드로 만들지 말 것. (검토 단계 자동분할이 이미지 위·아래에 HR을 형제 노드로 삽입하고 문단을 split 하려면 블록 노드여야 함)
 - CSS는 display: block 을 명시(네이티브·웹 동일). "인라인 미리보기"는 본문 흐름 안 표시를 뜻하며 PM inline 노드를 뜻하지 않는다.
 - 마크다운 직렬화(![alt](url), data-inline 속성 등)가 이 블록 이미지 노드로 round-trip(파싱·재직렬화) 되는지 확인한다.

[검증 기준 — 추가]
 1. stale cache로 작성·분할 진입 시 기존 텍스트가 즉시(또는 refetch 직후) 표시된다.
 2. ★ 입력 중에 refetch가 늦게 도착해도 작성 중이던 텍스트가 보존된다(덮어쓰기 없음). — on-01a·on-01b 둘 다 재현 테스트.
 3. 한 번 채워진 뒤 도착하는 refetch가 본문을 재초기화하지 않는다.
 4. 초기 주입이 자동저장을 잘못 트리거하지 않는다(빈/ stale 콘텐츠 저장 없음).
 5. 이미지 노드가 블록 레벨로 정의되어, 추후 검토 단계 자동분할(HR 형제 삽입·문단 split)과 호환된다.
 6. (기존) 사진 60%/280px, margin:12px 0, display:block, 원본 URL 보존 — 네이티브·웹 동일.
