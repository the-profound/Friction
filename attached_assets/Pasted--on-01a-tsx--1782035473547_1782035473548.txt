# 작업: "작성 후 나갔다 들어오면 텍스트가 사라지는" 버그 수정 (on-01a.tsx)

## 증상
텍스트 입력 → 사진 추가 → 작성 화면에서 뒤로 나갔다가 다시 들어오면 텍스트가
사라진다(사진만 남거나, 이전 상태가 저장됨). 빠르게 편집 후 이동할 때 발생.

## 근본 원인 (확정 진단)
WebView(TipTap) → RN 간 마크다운 export/autosave 파이프라인의 레이스 컨디션이다.
관련 파일: on-01a.tsx.

- [A] handleExportMarkdown(약 line 167)이 **requestId와 무관하게** 항상
  contentRef.current를 덮어쓴다. 그래서 이미지 삽입 직전에 발화된 stale한
  autosave 응답이 먼저 도착하면 contentRef가 "옛 내용"으로 오염된다.
- [B] getEditorContent()(약 line 160)가 editor 미준비 또는 2000ms timeout 시
  오염된 contentRef.current를 그대로 fallback으로 반환 → stale 내용이 저장된다.
- [C] 구조적 취약점: exportDebounce(1200ms) + autosaveDebounce(1200ms) = 최대 2.4초
  지연. 이 안에 화면을 벗어나면 최신 내용이 저장되지 못한다.

## 설계 원칙
1. **단조 증가하는 버전/시퀀스로 stale 응답을 무조건 폐기**한다. 오래된 응답이
   최신 상태를 덮어쓰는 일이 절대 없어야 한다.
2. **저장 직전에는 fallback(stale contentRef)이 아니라 "최신 강제 export"를 await**
   한다. 확신이 없으면 저장하지 않는다(데이터 손실 < 저장 지연).
3. **이탈/blur 시점에는 디바운스를 우회하고 즉시 flush**한다.

## 수정 사항 (이 순서로, 각 단계 후 검증)

### 1) [A 수정] export 응답에 버전 가드 추가
- 매 export 요청에 단조 증가 requestSeq(또는 docVersion)를 부여한다.
- handleExportMarkdown은 payload의 seq가 **현재까지 본 최신 seq 이상일 때만**
  contentRef.current(및 lastSeq)를 갱신한다. 더 오래된 응답은 폐기한다.
- pendingExportRef.resolve도 requestId 일치 시에만 호출(기존 조건 유지).

​
// 의사코드
const lastSeenSeqRef = useRef(0);
const handleExportMarkdown = useCallback((payload) => {
if (payload.seq < lastSeenSeqRef.current) return; // stale → 폐기
lastSeenSeqRef.current = payload.seq;
contentRef.current = payload.markdown;
if (pendingExportRef.current?.requestId === payload.requestId) {
pendingExportRef.current.resolve(payload.markdown);
pendingExportRef.current = null;
}
}, []);

### 2) [B 수정] getEditorContent의 stale fallback 제거
- editor 준비 상태이면, 항상 **새 export를 강제 요청**하고 그 requestId/seq에
  해당하는 응답만 resolve 한다.
- 2000ms timeout 시 **오염 가능성이 있는 contentRef를 그대로 반환하지 말 것.**
  대신 (a) 재요청 1회 → (b) 그래도 실패하면 reject 또는 "저장 보류" 신호 반환.
  저장 측은 이 경우 저장하지 않고 사용자에게 안내/재시도하게 한다.
- editor 미준비(!editorReady)일 때도 stale contentRef 즉시 반환을 지양하고,
  editorReady가 될 때까지 짧게 대기(또는 저장 보류) 후 최신값을 받아온다.

### 3) [C 수정] 이탈 시 즉시 flush (디바운스 우회)
- handleBack/blur/앱 백그라운드 전환 시:
  1. export/autosave 디바운스 타이머를 취소하고,
  2. **즉시 export를 요청해 최신 마크다운을 await**,
  3. 그 결과로만 doSave를 수행한다.
- 가능하면 export debounce와 autosave debounce를 **하나의 파이프라인으로 합치거나**,
  최소한 이탈 경로에서는 두 디바운스를 모두 건너뛰는 flush() 함수를 둔다.

### 4) WebView 메시지 순서 보장
- insertImage와 requestExportMarkdown이 WebView 큐에서 뒤섞이지 않도록,
  export 응답에 **그 응답이 캡처한 docVersion**을 함께 실어 보낸다(웹뷰 측에서
  현재 doc의 버전을 읽어 첨부). 소비자(RN)는 기대 버전보다 낮으면 폐기/재요청.

### 5) [방어선] 손실 방지 백업
- 이탈 직전 현재 contentRef(또는 강제 export 결과)를 로컬에 스냅샷 저장.
- 저장된 새 내용이 직전 알려진 길이보다 비정상적으로 짧으면(예: 텍스트가 통째
  사라짐) 곧장 덮어쓰지 말고 백업과 비교/경고 후 처리.

## 검증
- 로깅: export/autosave 시 requestId·seq·markdown 길이·이미지 수를 기록.
- 재현 테스트(반드시 통과):
  1. 빈 문서 → 이미지 삽입 → 이미지 아래 텍스트 타이핑 → 1200ms 이내 즉시 뒤로
     → 재진입 시 **텍스트+이미지 모두 보존**.
  2. 텍스트 → 이미지 → 빠른 연타 편집 후 즉시 이탈 → 최신 내용 보존.
  3. 느린 WebView 응답(인위적 지연 주입) 상황에서 stale 응답이 절대 최신을
     덮어쓰지 않음.
- 회귀: 정상 속도 편집 시 저장 동작/디바운스 효율이 깨지지 않는지 확인.

## 제약
- stale 데이터로 저장하느니 **저장을 보류/재시도**하는 쪽을 택하라.
- [A][B][C]를 가능한 한 별도 커밋으로 분리해 각 효과를 독립 검증할 수 있게 하라.
- 데이터 손실 위험이 있는 변경은 먼저 설명하고 진행하라.
