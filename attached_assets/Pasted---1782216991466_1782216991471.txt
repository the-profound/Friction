[역할] 너는 깨진 코드베이스를 "사진 기능이 들어오기 직전의 안전한 상태"로 되감고, 거기서부터 다시 진단을 시작하도록 돕는 엔지니어다. 롤백은 파괴적 작업이므로 아래 순서를 반드시 지켜라. 임의로 hard reset 하지 말고, 각 단계 결과를 보고하라.

[배경]
- 작성(on-01a)→검토(on-01b) 전환 시 본문이 비고 "내용을 작성해주세요" 모달로 막힘 + 사진이 원본 크기로 표시되는 버그가 있다.
- 최근 며칠간 검증되지 않은 패치가 여러 겹 쌓였다: (1) isDataFresh 게이트 제거, (2) useAutoSave.ts dirtyEpochRef 도입, (3) "초기 1회 주입 + dirty 가드", (4) editorHtml.ts / WebViewMarkdownEditorWeb.tsx 이미지 관련 변경.
- 이 패치들이 원래 버그와 뒤섞여 원인 구분이 불가능해졌다. 그래서 "사진 기능이 들어온 지점"으로 되감고 처음부터 다시 진단하려 한다.

────────────────────────
[Step 1 — 현재 상태 백업 (절대 생략 금지)]
 - 현재 작업 내용(커밋 안 된 변경 포함)을 잃지 않도록 백업한다.
   · 커밋되지 않은 변경이 있으면 먼저 임시 커밋하거나 stash.
   · 현재 HEAD에서 백업 브랜치 생성: 예) git branch backup/pre-rollback-20260623
 - 백업이 완료됐음을 확인하고 브랜치명을 보고하라. (이후 패치 내용을 다시 참고할 수 있어야 함)

[Step 2 — 사진 기능이 들어온 커밋 찾기]
 - git 히스토리를 조사해 "사진/이미지 기능"이 처음 도입된 커밋을 찾아라.
   · git log --oneline 으로 최근 히스토리를 나열.
   · 커밋 메시지/변경 파일에서 사진·이미지 관련 단서 검색: "사진", "image", "photo", "inlineImage", "tiptap-inline-image", "insertImage", editorHtml.ts, WebViewMarkdownEditorWeb.tsx 등.
 - 다음 두 지점을 각각 커밋 해시와 함께 명확히 보고하라:
   (A) 사진 기능이 들어오기 "직전"의 마지막 커밋 (= 깨끗한 baseline 후보)
   (B) 사진 기능이 처음 들어온 커밋
 - 위 (1)~(4) 패치 각각이 어느 커밋에 있는지도 매핑해서 보여라.
 - ★ 여기서 멈추고, 어디로 되감을지 내가 고를 수 있게 후보를 제시하라. (기본 권장: (A) 사진 기능 직전의 깨끗한 baseline)

[Step 3 — 롤백 (내가 타깃 커밋을 확정한 뒤에만 실행)]
 - 내가 지정한 커밋으로 되감되, 히스토리를 파괴하지 않는 방식을 우선한다:
   · 권장: 그 커밋에서 새 작업 브랜치를 만들어 거기서 진행 (git switch -c rework/photo-feature <해시>)
   · 또는 git revert로 문제 커밋들만 되돌림.
   · hard reset이 꼭 필요하면 Step 1 백업이 있는지 재확인 후에만.
 - 롤백 후 현재 HEAD 해시와 브랜치를 보고하라.

[Step 4 — baseline 재진단 (처음부터)]
 롤백된 상태에서, 사진 기능을 다시 넣기 전에 기준 동작을 확인하라:
 - (a) 작성 화면에서 본문 입력 → "검토" 전환이 정상인가? "내용을 작성해주세요" 모달 없이 넘어가는가?
 - (b) 검토 화면에서 기존 텍스트가 정상 표시되는가?
 - (c) (사진 기능이 이 시점에 있다면) 사진 첨부 시 동작/크기는 어떤가?
 결과를 보고하고, "원래 버그(텍스트 미표시·사진 원본 크기)가 이 baseline에 이미 있었는지 / 사진 기능 도입과 함께 생겼는지"를 사실로 결론지어라.

────────────────────────
[보고 형식]
 A. 백업 브랜치명.
 B. git 히스토리 요약 + (A)baseline 후보 / (B)사진 기능 도입 커밋 해시 + 패치(1~4) 위치 매핑.
 C. (롤백 후) 현재 HEAD/브랜치.
 D. baseline 재진단 결과 (a/b/c) + "버그가 언제부터 있었나" 결론.
 ※ Step 2 이후에는 내 확정 없이 Step 3 롤백을 실행하지 말 것.
