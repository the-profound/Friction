[역할] 너는 이 코드베이스를 진단하는 디버깅 엔지니어다. 아직 코드를 수정하지 마라. 먼저 원인을 진단하고, 근거(파일 경로·라인·코드 스니펫)와 함께 보고하라. 수정 제안은 진단이 끝난 뒤 별도 섹션에 적어라.

[제품 맥락]
- 글쓰기 플로우는 작성(DRAFT) → 검토/분할 → 마감(CLOSING) 3단계다.
- 에디터는 TipTap 기반 마크다운 에디터이며, 자동 저장이 연동되어 있다.
- 작성 단계: 본문 텍스트 입력 + 커서(포인터) 위치에 사진을 "인라인 미리보기"로 삽입.
- 검토/분할 단계: 사진 위·아래에 분할선이 자동 생성되어 사진이 단독 페이지로 분리됨.

[현재 시뮬레이션에서 관찰된 버그]
1. 작성 단계와 분할 단계에서 텍스트 입력란에 "텍스트가 로드되지 않는다"(보이지 않는다).
2. 사진을 첨부하면 기획한 미리보기 크기가 아니라 원본 크기 그대로 들어가 화면을 전부 덮는다.

[진단 과제 1 — 텍스트가 보이지 않는 문제]
다음을 순서대로 추적하고 각 항목에 사실(코드 근거)로 답하라.

(1) 데이터 흐름 추적: 텍스트가 입력 → 상태(state/store) → 영속화(자동 저장/localStorage/DB/API) → 다시 로드되어 에디터에 주입되는 전체 경로를 그려라. 각 단계의 함수/파일/라인을 명시하라.
(2) 단계 구분:
   - (a) 데이터 자체가 비어 있는가(저장이 안 됨/덮어써짐/초기화됨), 아니면
   - (b) 데이터는 있는데 렌더링/주입만 안 되는가(에디터 content 주입 누락, 빈 값으로 setContent, 조건부 렌더 오류 등)?
   둘 중 무엇인지 콘솔/네트워크/상태값으로 확인 가능한 방법과 함께 결론지어라.
(3) 시뮬레이션 vs 실제 로직: 이 현상이 시뮬레이션(목 데이터/시드/프리뷰 모드) 고유의 문제인지, 실제 에디터·저장 로직의 문제인지 구분하라. 시뮬레이션 전용 코드 경로가 있다면 어디서 분기되는지 보여라.
(4) 특정 행동에서 데이터가 사라지는가: 단계 전환(작성→검토/분할), 자동 저장 타이밍, 리마운트/리렌더, 라우팅 이동, 사진 삽입 직후 등 "어떤 액션을 트리거할 때" 텍스트가 사라지는지 재현 시나리오를 찾아라. 의심되는 이벤트 핸들러/useEffect/의존성 배열을 지목하라.
(5) 작성 단계와 분할 단계가 같은 원인인지, 서로 다른 원인인지 판단하라.

[진단 과제 2 — 사진 크기 문제]
(1) 삽입된 이미지에 실제로 적용되는 크기 설정(인라인 스타일, CSS 클래스, TipTap 이미지 노드의 attrs/렌더링)을 모두 찾아 현재 값 그대로 보고하라.
(2) 현재 코드가 적용 중인 값과 아래 기획 기준을 비교하고, 어긋난 지점을 표로 정리하라.

   [기획 기준 — 작성 단계 인라인 미리보기]
   - display: block  (현재 inline이면 글자 베이스라인에 박혀 줄 높이가 흔들림 → 문제)
   - max-width: 60%  (고정 px가 아니라 본문 컬럼 폭 기준 %)
   - max-height: 280px (세로로 긴 사진 방어)
   - width: auto / height: auto, 원본 종횡비 유지(크롭 금지)
   - margin: 12px 0 (좌측 정렬 유지)
   - 표시 크기만 줄이고 원본(원래 해상도)은 반드시 보존해야 함

   ※ 참고: 이전 적용값으로 추정되는 `max-width: 120px; display: inline;` 패턴이 남아 있는지, 혹은 크기 제약 자체가 누락되어 원본 크기로 렌더되는지 확인하라.
(3) "원본 크기로 들어간다"의 원인이 (a) CSS가 아예 적용되지 않음(클래스명 불일치/스코프 문제), (b) max-width/max-height 제약 누락, (c) 인라인 스타일이 CSS를 덮어씀, (d) 이미지 노드가 width 속성을 원본 픽셀로 하드코딩, 중 무엇인지 지목하라.
(4) 원본 해상도 보존 로직이 존재하는지(표시 크기와 저장 원본이 분리되어 있는지) 확인하라. 마감 단계에서 원래 크기·해상도로 표시하려면 원본이 보존돼야 한다.

B. 원인 진단: 과제별로 "근본 원인 + 코드 근거(파일·라인·스니펫)".
