# 단상과 작성 중 단계 초안 통합

작성 중 단계의 데이터를 Article 테이블이 아니라 thoughts 테이블에 보관하는 것으로 단상과 작성 중 단계 초안을 통합합니다. 단 단상의 텍스트는 이제 마크다운을 지원합니다. 추가적으로 통합에 필요한 조치들이 있다면 실행합니다.

진짜 단상과 작성 중 초안은 데이터상 따로 구분하지 않습니다. 대신 thoughts 테이블에 state 열을 추가해 일반 단상과 예비 단상(질문에서 나온 상태)을 구분합니다.

생각 재점화 위젯은 폐지합니다. widget_slot 테이블과 위젯 생성 알고리즘(타입 추첨, 후보 생성 및 평가 등)은 더 이상 사용하지 않습니다. 질문은 위젯이 아니라 기록 목록의 카드로 노출됩니다.

# 기록함 UI 기록 목록 화면 완전 개편

이것을 시작으로 기록함의 UI를 전면 재개편합니다. 단상, 메모, 편지의 세 분류를, 단상(작성 단계 초안 포함), 편집(검토&마감 단계 초안), 편지로 구분합니다. 

단 이때 탭을 분리하지는 않습니다. 세 컴포넌트를 모두 한 곳에 나열하고 필터 기능으로 분류합니다. 기본 나열은 최신순으로 합니다. 

## 필터 설정

[공간 목록] 화면에서의 필터 UI 컴포넌트를 Friction의 기본 필터 컴포넌트로 분류하여 저장합니다. 

기록함의 기본 화면인 [기록 목록] 화면에도 그 기본 필터 컴포넌트를 사용합니다. 이때 필터는 두 기록의 종류를 고르는 필터(단상(기본), 편집, 편지)와 보기 방법을 변경하는 필터(하나씩(기본), 내용도, 제목만)으로 두 종류로 구성합니다. 

완성되어 내보내기된 편지도 기록 목록에 함께 포함합니다. 다만 세 분류를 한 번에 모아 보는 옵션은 필터에 두지 않아, 전체 종류를 한꺼번에 보는 화면은 없습니다.

### [하나씩]

[하나씩] 보기에서는 다음의 규칙에 따라 한 화면에 하나의 기록만을 보여줍니다. 

1. 제목이 있는 편집 중인 초안이나 편지의 경우에는 기존 수신함 화면에서 사용하는 5:8 비율의 카드를 재활용하여 목록을 형성합니다.
2. 단상의 경우에도 마찬가지로 같은 5:8비율 카드를 틀로 활용하되, 카드에 표지와 제목 등을 뜨는 게 아니라, 본문 전체를 보이게 합니다.
    1. 이때 위아래 동일한 여백을 주고, 한 화면에 담기지 않는 내용이 있다면 … 을 활용하는 방식으로 생략합니다. 이때 한 화면에 넘치는지 판단 여부는 기존에 검토 단계에서 pretext를 활용해 길이를 계산하는 로직을 활용합니다.
3. 꾹 누를 시 삭제할 것인지 물어봅니다.

### [내용도]

[내용도] 보기에서는 제목과 내용을 아래의 규칙에 따라 보여줍니다. (별개의 작업으로 모든 화면에 적용되는 폰트 파일 수정: 기존 8cqi였던 [제목] 텍스트 크기를 제목1 서식 텍스트와 마찬가지로 6.9cqi로 변경합니다.)

1. 제목은 6.9 cqi로 보여주고 줄바꿈 상태를 보존한 채로 표시합니다.
2. 본문은 다음의 규칙에 따라 표시합니다.
    1. 4cqi로 세 줄만 보여줍니다. 
    2. 줄바꿈 문자 앞뒤에 공백이 있는 경우 줄바꿈 문자를 제거한 채로 보여줍니다. 
    3. 줄바꿈 문자 앞뒤에 공백이 없는 경우에는 줄바꿈 문자를 공백으로 변경하여 보여줍니다. 
    4. 여러 칸의 공백은 한 칸의 공백으로 보여줍니다. 
3. 단상의 경우에는 아래 규칙을 따라 보여줍니다.
    1. 제목1 서식이 맨 첫 줄에 있다면 그것을 제목으로 인식하여 보여줍니다.
    2. 제목1 서식이 맨 첫 줄에 없는 경우 본문 내용을 다섯 줄 보여줍니다.
4. 꾹 누를 시 삭제할 것인지 물어봅니다.

### [제목만]

[제목만] 보기에서는 제목이 있으면 제목을 한 줄로 보여주고 본문만 있다면 본문 초반부를 보여줍니다. 이때 줄바꿈은 제거하고 줄바꿈 전후에 공백이 없다면 공백 하나 추가합니다. 여러 개의 공백은 생략합니다. 현재의 메모 탭 목록을 참고합니다.

# 질문을 보여주고 활용하는 방식

- 질문은 기록 종류 필터가 [단상]인 경우에 표시됩니다.
- 질문 카드는 기록 목록 대기열의 첫 번째에 배치됩니다.
- 질문은 예비 단상입니다. 한 줄 질문은 제목1 서식으로 맨 첫 줄에 두고, 세부 설명을 본문에 작성합니다.
- 한줄 질문 앞에는 “Q.”를 꼭 붙입니다.
- 기본적으로 단상과 동일한 카드 UI로 기록 목록 화면에 표시됩니다. 이때 그림자만 friction 기본 적색으로 표시됩니다.
- 질문 카드를 누르면 내용을 그대로 유지한 채로 단상 작성 화면으로 넘어가고 예비 단상에서 일반 단상으로 변경되어 저장됩니다.
- 화면을 위에서 아래로 스와이프해 새로고침하거나 질문 카드를 눌러 답변하러 들어가는 순간, 대기 중인 다음 질문으로 교체됩니다. 지나간 질문은 다시 볼 수 없습니다.
- 근거가 된 단상·인용을 접어두었다가 펼치는 기능은 두지 않습니다. 작성 화면에서는 처음부터 노출하지 않고, 삽입을 눌렀을 때만 그 근거 기록이 추천 목록 상단에 먼저 노출됩니다.
- 질문이 일반 단상으로 승격된 뒤에도 근거 기록과의 연결은 그대로 유지됩니다.

# 초안 작성 화면 변경

## 단상 작성 화면

- 기존의 단상 작성 화면은 사용하지 않습니다. 제거해주십시오.
- 제목을 제거한 메모 초안 작성 화면을 기본 단상 작성화면으로 사용합니다.
- 맨 위의 슬라이드에서의 이름을 [작성]에서 [단상]으로 변경합니다.
- 첫 줄은 기본적으로 제목1 서식으로 시작합니다.

## 단상 → 편집 승격 규칙

- 제목은 첫 줄이 제목1 서식일 때 그 블록 텍스트를 그대로 사용합니다. 첫 줄이 본문 서식이면 제목은 빈 값으로 둡니다.
- 제목이 빈 상태에서는 목록 화면으로 돌아가려 해도 이동을 막습니다.
- 앱 종료 등으로 중간에 이탈할 수 있는 경우에는 편집 단계로 승격시키지 않고 단상 상태로 유지합니다.

## 검토 및 마감 단계 화면

- 기존의 화면을 그대로 사용합니다.
