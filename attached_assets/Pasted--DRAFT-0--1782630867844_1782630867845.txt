# 작업: 작성(DRAFT) 화면 - 사진(미디어) 인라인 추가 기능 구현

## 0. 최우선 제약 (반드시 지킬 것)
- 이 작업의 목표는 "작성 화면에 사진을 인라인으로 추가하는 것" 하나뿐이다.
- 지난 구현에서 사진 추가 기능을 건드리다가 **본문 텍스트가 저장되지 않는 치명적 버그**가 발생했다.
- 따라서 **본문 텍스트의 입력/저장(자동 저장) 로직을 절대 수정하지 마라.**
  - TipTap의 텍스트 노드, onUpdate/onChange, 자동 저장(debounce/persist) 파이프라인, 직렬화(serialize)·역직렬화(parse) 로직을 변경 금지.
  - 이미지 노드를 추가하더라도, 기존 텍스트 직렬화가 깨지지 않는지(저장 후 새로고침 시 본문이 그대로 남는지) 반드시 확인하라.
- 사진 삽입은 **기존 문서 상태(state)에 이미지 노드를 더하는 방식**이어야 하며, 기존 본문 콘텐츠를 재작성/덮어쓰기 해서는 안 된다.

## 1. 기능 개요
작성(DRAFT) 화면에서, 사용자가 글을 쓰던 흐름을 끊지 않고 사진을 **커서 위치에 인라인으로** 즉시 첨부할 수 있게 한다.
- 핵심 원칙: **작성 몰입을 방해하지 않는다.** (정밀한 크기 조정/정렬/페이지 분리는 이후 검토 단계의 책임이며, 이번 작업 범위가 아님)

## 2. 구현 범위

### 2-1. 진입 — 마크다운 툴바에 "미디어 추가" 버튼 신설
- 작성 화면의 마크다운 툴바에 "미디어 추가" 버튼을 추가한다.
- 텍스트 서식 버튼들과 같은 줄에 배치하여, 글 쓰던 손 흐름 그대로 호출되게 한다.

### 2-2. 소스 선택 — 카메라 / 갤러리
- 버튼을 누르면 "카메라 촬영 / 갤러리(기기 제공)" 중 선택하는 시트(액션 시트)를 띄운다.
- 촬영하거나 선택한 사진을 즉시 본문에 삽입한다.

### 2-3. 첨부 방식 — 커서(포인터) 위치 인라인 삽입
- 사진은 **현재 커서가 놓인 위치**에 삽입된다.
- 작성 단계에서는 페이지 분리(자동 분할선)를 적용하지 않는다. 본문 흐름 안 인라인으로만 들어간다.

### 2-4. 크기 — '미리보기' 인라인 (원본 보존)
- 표시 크기만 미리보기로 줄이고, **원본(원래 해상도)은 반드시 보존**한다. (마감 단계에서 원래 크기·해상도로 다시 보여줘야 하므로 원본 데이터를 버리지 말 것)
- 아이콘 수준 썸네일이 아니라, "이 자리에 이 사진이 들어간다"를 분명히 인지시키는 미리보기 크기.

## 3. CSS 스펙 (이미지 노드 표시)
현재 적용된 `max-width: 120px; display: inline;` 의 문제 3가지를 고쳐라.
1. `display: inline` → 글자 베이스라인에 박혀 줄 높이가 흔들림 (아이콘처럼 보임)
2. `120px` 고정값 → 기기 폭에 따라 점유 비율이 달라짐
3. `max-height` 부재 → 세로로 긴 사진이 화면을 덮음

적용할 스펙:
​
.tiptap-inline-image {
display: block;        / inline → block: 글자 사이에서 빼내 한 줄로 /
margin: 12px 0;        / 위아래 여백 (좌측 축 정렬 유지) /
width: auto;
max-width: 60%;        / 고정 px 대신 본문 컬럼 폭 기준 % /
max-height: 280px;     / 세로 긴 사진 방어 /
height: auto;
border-radius: 8px;    / 선택: 부드러운 모서리 /
}
- 원본 종횡비를 그대로 유지하고(크롭 금지) 폭·높이 상한 박스만 씌운다.
- 60% / 280px 수치는 화면에서 미세 조정 가능하도록 분리/상수화해 두라.

## 4. 에디터 연동 (TipTap)
- TipTap 기반 마크다운 에디터에 이미지 노드를 처리하되, **자동 저장 연동이 깨지지 않도록** 한다.
- 이미지 노드도 직렬화/역직렬화가 되어, 저장 후 재진입 시 사진이 본문 텍스트와 함께 그대로 복원되어야 한다.

## 5. 이번 작업에서 하지 말 것 (Out of scope)
- 검토 단계의 자동 분할선(사진 위·아래 분할선) 생성 로직 → 구현하지 마라.
- 사진 1장=1페이지 단독 분리, 마감 단계의 원래 크기 렌더링 → 이번 범위 아님.
- 본문 텍스트 입력/저장 로직 수정 → 절대 금지(0번 항목).

## 6. 완료 기준 (반드시 검증)
1. 툴바 "미디어 추가" → 카메라/갤러리 선택 → 커서 위치에 사진이 인라인(block, max-width 60%, max-height 280px)으로 삽입된다.
2. 삽입된 사진의 원본 해상도 데이터가 보존되어 있다.
3. **사진을 삽입하고 저장 → 새로고침해도 본문 텍스트와 사진이 모두 그대로 남아있다.** (지난 버그 재발 여부를 이 시나리오로 반드시 확인할 것)
4. 사진을 전혀 추가하지 않은 일반 글 작성/저장 동작이 기존과 100% 동일하게 유지된다.
